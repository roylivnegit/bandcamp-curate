**Cut the feed by requiring more than one stranger**

- _title_: Cut the feed by requiring more than one stranger
- _problem_: The feed has about 1,600 records in it, so nobody reads it. The reason is that a record only needs one other person to own it before we call it a recommendation, and we treat a collector who owns 8,000 records the same as one who owns 200 and shares 40% of Roy's taste.
- _proposal_: Two changes to scoring, measured separately so we learn which one did the work. First, a minimum co-ownership floor before an item is stored at all. Second, weight each neighbour by how much their collection actually overlaps Roy's, divided by how big their collection is — a 40%-overlap collector should outvote a completionist. Report the feed size and the score distribution at each step against the sandbox corpus, and keep the old behaviour reachable behind a config value so we can compare rather than argue.
- _why now_: The backlog listed three possible causes for the 1,600 and picked none. The code answers it: there is no threshold and no neighbour weighting. This is the shortest path from 1,600 plausible records to a list Roy would read to the bottom.
- _surface_: curation
- _effort_: M
- _measure_: Feed size after the change. What share of the surviving recommendations have more than one co-owner. How far down the list the reasons still look believable when Roy reads it. Kill it if cutting the tail also cuts the records he would have bought.
- _kill criteria_: If a floor of 2 or 3 co-owners removes most of the feed but the top 50 is unchanged, the floor was cosmetic and the real problem is ranking, not volume — say so and move to neighbour weighting alone.
- _evidence_:
    - backend/app/curation/engine.py:377 — every album with at least one co-owning neighbour is scored and stored; no minimum
    - backend/app/curation/engine.py:386 — score = 1.0*co_owners + 0.25*tag_affinity, so a single stranger scores 1.0

## 3 · Design

**[architect] ADR-0001**

- _title_: ADR-0001 — Cut the feed by requiring more than one stranger (curation co-ownership floor)
- _problem_: One stranger owning a record is enough to call it a recommendation. The two grouped candidate queries (engine.py:355-366 albums, engine.py:404-416 tracks) count distinct co-owning neighbours per item with no minimum, and engine.py:386 scores a single co-owner at 1.0. The result is a ~1,600-row feed that is mostly items where exactly one collector agreed with Roy once. one_per_band dedup (engine.py:441) shrinks the list but not the noise — it picks each band's top item, it does not require agreement. We want a floor on how many distinct neighbours must own an item, shipped so today's behaviour stays the default and the new behaviour is measurable against it.
- _approach_: The floor is a threshold on the two candidate queries, not a new filter and not a new module. compute_recommendations gains min_co_owners / min_neighbours_for_floor (None → get_settings(), which is @lru_cache'd at config.py:130, so tests pass explicit ints) plus an optional stats_out dict. New settings: curation_min_co_owners = 1 (today's behaviour, new path opt-in) and curation_min_neighbours_for_floor = 25 (one popular album's supporter page yielded 17 neighbours on the live 2026-07-24 run, so below ~25 "two strangers" is a sampling artefact of how much we crawled). The floor is active iff min_co_owners > 1 AND len(neighbours) >= the gate; when inactive no HAVING clause is emitted at all, so the default path emits today's SQL and parity is structural rather than arithmetic. When active, .having(count(distinct FanItem.fan_id) >= floor) goes on BOTH grouped queries, because one_per_band runs after scoring and an album-only floor lets a cut band walk back in through a 1-co-owner track. stats_out is filled with min_co_owners, neighbours, floor_applied, bands_cut_no_multi_co_owner and merged into scan.stats at scan_service.py:366 and :437 (already JSON — no schema change). The cut-band number is computed only when the floor is active, via two extra grouped queries of the same shape with HAVING count < floor, run through the same exclusion predicates, minus the surviving band ids.
